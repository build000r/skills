# Plan Execution

The accepted plan and existing task tracker define scope and completion. Reuse
existing tasks; when needed, create one execution graph with dependencies,
acceptance criteria, validation, write ownership and the selected model/substrate.
Hand its ready frontier to divide-and-conquer. Tracked native Codex agents are
valid; persistent external panes are optional when their capabilities are needed.

Workers implement disjoint concerns and report their actual diffs and validation.
Shared files have one owner. Preserve concurrent work and resolve target repos
before Git commands. Do not create worktrees solely for disjoint-file work.
A required isolated checkout has a named integration and retirement owner.

Review the final behavior independently against the accepted plan and required
checks. Auth/payments/identity work must reuse canonical configured packages;
record real gaps instead of inventing replacements. Validate unpublished package
changes against the actual delivery target before claiming delivered acceptance.
Production-data changes require the applicable transition/recovery plan.

Fix material findings and recheck their affected behavior and new risks. Reuse a
reviewer when useful. Additional hardening or fresh review needs a specific
unresolved risk or explicit requirement. Completion is accepted behavior, passing
required checks and no unresolved material finding. Honor explicitly requested
scoring, but do not invent a 100/100 or structural-score gate.

If a fix repeats without progress, identify the blocking evidence, decision or
external dependency. Do not keep launching the same worker on the same brief.
Continue authorized independent work and raise only the actual blocker.

Close accepted tasks, record concise validation and commit identities, and commit
scoped changes across affected repos. Update an existing plan index only when it
is the task's canonical store. No automatic COMPLETED.md, AUDIT_REPORT.md,
workgraph, diagram, review commit, archive or invocation history is required.
Use temporary files only for actual consumers and remove obsolete scratch after
workers finish and evidence is collected. Preserve unique recovery bytes until
their named dependency is resolved. Report remaining work honestly.
